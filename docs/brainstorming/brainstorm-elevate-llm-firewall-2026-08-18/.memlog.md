It swaps secrets for tokens (e.g., [REDACTED_1]) on the way out, and swaps them back into real values when the LLM generates code/commands. The harness stays perfectly unaware, and context isn't polluted.

- (technique) started Disney Method
- (idea by user) Dreamer: A state-of-the-art detection engine with a full professional-grade pipeline — not a toy regex scanner, but something that could be published as a paper.
- (idea by coach) Dreamer: A 4-tier detection pipeline: (1) Aho-Corasick + regex for known patterns at near-zero cost, (2) entropy analysis to catch high-entropy strings like API keys without patterns, (3) quantized BERT NER for named entities, (4) a lightweight context-aware classifier that understands 'this is a connection string in a config file' vs 'this is example code in a README'. Each tier has a published F1 score and latency benchmark.
- (idea by coach) Realist: Prioritize Tier 2 (Entropy Analysis) as the next build. Reasons: (1) It's novel — no competing tool does this well, (2) it's implementable in a weekend (Shannon entropy on sliding windows), (3) it shows algorithmic originality not just library usage, (4) it catches unknown API keys/tokens that regex misses, which makes the scare report way more impressive. Tier 1 Aho-Corasick upgrade and Tier 3 NER polish come after.
- (idea by coach) Critic solution: Don't do blind entropy — do CONTEXTUAL entropy. Score the string's entropy AND check what's around it. High-entropy string next to 'api_key=' or 'secret:' → almost certainly a real secret (high confidence, redact). High-entropy string inside a base64 image data URI or UUID column → safe (suppress). This turns entropy analysis from a dumb scanner into an intelligent detector. Assign a confidence score 0-1 to every detection, and only redact above a tunable threshold (default 0.7). Publish the precision/recall curve in the README.
