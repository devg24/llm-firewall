- (decision) Q1 RESOLVED — Tier 4 classifier: Lightweight tree-based model (XGBoost/LightGBM) or quantized encoder (DeBERTa-v3-mini/ModernBERT) via ort/candle. Only executes on borderline spans (confidence 0.5-0.7). 10-25ms latency budget. Training data from CodeSearchNet/Stack v2 (positive: commits followed by key rotation; negative: test dirs, docs, mock fixtures). Feature input: filepath + AST node type via tree-sitter + contextual text.
- (decision) Q2 RESOLVED — Proxy mechanisms: Claude Code respects HTTP_PROXY/HTTPS_PROXY and ANTHROPIC_BASE_URL (prefer HTTP_PROXY to avoid modifying base URL). Cursor requires patching settings.json: http.proxy, http.proxySupport=override, http.proxyStrictSSL=false, cursor.general.disableHttp2=true. Copilot uses standard VS Code http.proxy settings.
- (decision) Q3 RESOLVED — Streaming re-injection: Stateful Streaming Aho-Corasick automaton with hold-back window. Partial matches at chunk boundaries are withheld until next chunk resolves them. Fixed-size ring buffer sized to max placeholder token length for zero-allocation on hot path. Wrapped in tokio AsyncRead/Stream adapter for SSE payloads.
- (decision) Q4 RESOLVED — Per-tier thresholds, not global. Tier 1 bypasses thresholds entirely (deterministic patterns). Tier 2 entropy is domain-sensitive (default 0.6, but auto-detected domain profiles shift it, e.g. crypto repos → 0.85). ThresholdConfig struct per tier. Merge step only acts as tie-breaker for overlapping spans using relative confidence gap above per-tier threshold.
- (note) VERIFICATION Q1: xgboost Rust crate is a thin FFI wrapper with limited ecosystem maturity. Recommend ort (ONNX Runtime for Rust) as primary inference path — train in Python, export ONNX, run in Rust via ort. More battle-tested, supports both tree models and encoder models through a single runtime. candle remains the fallback for BERT NER (Tier 3) since it's already integrated.
- (note) VERIFICATION Q2: User prefers HTTP_PROXY over ANTHROPIC_BASE_URL override. HTTP_PROXY is viable but requires the proxy to handle TLS termination and re-encryption (MITM). This means Guardian-AI must generate a local CA certificate and add it to the system trust store on activation — or use CONNECT tunneling and inspect at the TLS layer. The http.proxyStrictSSL=false approach for Cursor bypasses this but weakens TLS guarantees. NEW RECOMMENDATION: Auto-generate a local CA cert during 'llm-firewall on', trust it via 'security add-trusted-cert' (macOS) / 'update-ca-certificates' (Linux), and set proxyStrictSSL=true. More secure and more professional.
- (note) VERIFICATION Q3: The SSE re-injection should operate on parsed SSE data fields, not raw TCP bytes. SSE has a specific framing format ('data: ...\n\n'). Injecting into raw bytes could corrupt SSE delimiters. Parse each SSE event, apply Aho-Corasick on the data payload, then re-serialize. The hold-back window applies at the SSE event level for partial tokens spanning events, not at the byte level.
- (note) VERIFICATION Q4: Domain auto-detection from Cargo.toml/package.json dependencies is clever. Add a new capability: CAP-9 for domain profile auto-detection. Also note: per-tier thresholds introduce a new config surface. Keep defaults opinionated and auto-detected; only expose overrides via an optional .guardian.toml for power users.
- (capability) CAP-9: Domain profile auto-detection — scan project dependency manifests (Cargo.toml, package.json, go.mod, requirements.txt) to auto-detect domain (e.g. crypto, healthcare, fintech) and adjust per-tier confidence thresholds accordingly.
- (constraint) Local CA certificate generation: On activation, Guardian-AI generates a local CA cert and trusts it in the OS trust store rather than disabling TLS verification. Maintains security posture.
