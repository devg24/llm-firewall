- (decision) Single binary with clap subcommands (on/off/serve/scan/stats/report). Crate workspace: guardian-core (detection pipeline, redaction, session state), guardian-proxy (axum server, SSE streaming, bidirectional interception), guardian-cli (clap entrypoint, scare report, tool patching, stats). CLI depends on both core and proxy. Proxy depends on core. One published artifact. Binds: crate boundary and dependency direction. Prevents: circular dependencies, monolithic single-crate growth that blocks contributor onboarding.
- (decision) Per-request-response-pair scoped state (Option B). Each outbound completions request creates an Arc<TokenMap> shared between the outbound handler and the inbound SSE response streaming task. Map lives only as long as the HTTP request-response cycle. No cross-request session state. No eviction logic. Completions APIs are stateless by design (full conversation history in every call), so per-request scoping is sufficient. Binds: guardian-core session state model, guardian-proxy handler lifecycle. Prevents: memory leaks from orphaned sessions, crash-state-loss bugs, unnecessary complexity of session management and eviction. Evolves AD-6 from 'destroy on request completion' to 'shared across request-response pair via Arc, destroyed on stream completion'.
- (decision) Trait-based detection pipeline in guardian-core. Detector trait with detect(&self, input: &DetectionInput) -> Vec<Span> signature. Each span carries confidence score and tier origin. Pipeline runner (orchestrator) owns: tier ordering, cascade logic (Tier 4 only on borderline 0.5-0.7 spans), per-tier threshold application, and overlap resolution. No tier applies its own threshold. Each tier is independently testable and benchmarkable. Binds: guardian-core detection API surface, span/confidence contract between tiers. Prevents: tiers making incompatible span format or threshold decisions, tightly coupled detection stages blocking independent development.
- (decision) Inbound streaming re-injection uses high-level async stream combinators (e.g., async-stream macro or tokio StreamExt) rather than manual poll_next implementations. Stream holds the Arc<TokenMap> and stateful Aho-Corasick automaton. Binds: guardian-proxy inbound response handling. Prevents: unsafe/complex Pin and Waker bugs, dropped SSE events due to manual polling errors, unmaintainable state machine code.
- (decision) Context-aware output scanning (CAP-8) uses a Sliding Lookbehind Buffer (Option A) within the stream. Maintains a rolling ~512-byte window of decoded output; when a placeholder is matched, heuristics run against the buffer to detect dangerous sinks (curl, logging, network commands). If dangerous, token is quarantined. Binds: guardian-proxy stream mutator. Prevents: breaking SSE streaming UX with bursty buffering, while mitigating prompt-injection exfiltration vectors. Note on Threat Model: Guardian-AI protects against accidental provider exfiltration and prompt-injected LLM exfiltration; it assumes the host developer is trusted.
- (decision) CLI lifecycle uses a Foreground Orchestrator (Option A). 'llm-firewall on' applies proxy settings to the OS/tools and blocks, running the proxy server in the foreground. Graceful shutdown on Ctrl+C restores all settings and removes the CA cert. Binds: guardian-cli process model. Prevents: orphaned background processes, broken network state if daemon crashes silently, complex PID tracking. Prioritizes reliability and visibility over pure invisibility.
