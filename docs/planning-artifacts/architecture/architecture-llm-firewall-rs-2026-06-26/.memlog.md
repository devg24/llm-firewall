- (event) Initialized workspace in Coaching Path
- (direction) Targeting a stateless proxy paradigm using Axum, Tokio, and Candle-core NER
- (question) How should we isolate the CPU-bound NER model inference from the Tokio async executor to avoid event loop starvation under load?
- (question) What JSON parsing strategy should we use for payload interception (Full schema deserialization vs. targeted field patching)?
- (decision) AD-1: ML Inference Isolation. Binds: Axum handlers to tokio::task::spawn_blocking. Prevents: CPU-bound candle-core inference from blocking async IO executor. Rule: Wrap HuggingFace Candle forward pass in tokio::task::spawn_blocking.
- (decision) AD-2: Forwards-Compatible JSON Interception. Binds: Interception engine to targeted JSON modification using serde_json::Value. Prevents: Schema drift and breaks due to upstream OpenAI completions API modifications. Rule: Extract, modify, and re-inject message content fields inside the untyped JSON payload.
- (decision) AD-3: Regex compilation and lifecycle. Binds: Interception engine to pre-compiled regex set. Prevents: High latency from compiling regexes on every incoming request. Rule: Compile regex patterns exactly once at startup and share them via thread-safe static structures (std::sync::OnceLock).
- (question) How should the HuggingFace candle-core NER model weights and tokenizer config be loaded (Download dynamically via hf-hub at startup vs. expect a local path on disk)?
- (question) What is the security fail policy if the ML engine or regex engine encounters a runtime error or timeout (Fail-closed returning 500 vs. fail-open passing unmodified payload)?
- (decision) AD-4: Local Model Loading with Configurable Paths. Binds: ML Engine to local filesystem paths. Prevents: Network dependencies at startup and air-gapped deployment failures. Rule: Load model assets (.safetensors, tokenizer.json) from local paths specified by environment variables, defaulting to a relative ./model/ folder. Provide a scripts/setup_model.sh helper script to easily download models for local development.
- (decision) AD-5: Fail-Closed Security Policy. Binds: Interception engine behavior on error. Prevents: Accidental exposure/leakage of raw PII to external APIs during pipeline failures. Rule: Return an HTTP 500 response immediately if JSON parsing, regex evaluation, or ML inference fails or times out.
- (question) What redaction token replacement strategy should be used (Simple static tokens like [REDACTED_NAME] vs. co-reference preserving unique tokens like [REDACTED_NAME_1] generated per-request)?
- (question) Should the upstream API base URL be configurable via environment variables (e.g., UPSTREAM_URL) to support alternative OpenAI-compatible gateways or Azure OpenAI, and should we reuse a single pooled HTTP client?
- (decision) AD-6: Co-Reference Preserving 1-Way Redaction. Binds: Redaction engine replacement logic. Prevents: Loss of semantic context (who-is-who) in the prompt forwarded to the upstream LLM. Rule: Within a single request, map each unique detected PII entity value to a unique indexed semantic token (e.g., [REDACTED_NAME_1]). The mapping is ephemeral, created per-request, and discarded immediately after processing.
- (decision) AD-7: Upstream Gateway and Connection Invariants. Binds: Proxy routing engine and HTTP client config. Prevents: Protocol lock-in and connection latency spikes. Rule: Read target base URL from UPSTREAM_URL environment variable (default: https://api.openai.com). Transparently proxy all endpoints, applying redaction only to POST /v1/chat/completions. Share a single, thread-safe, pre-configured reqwest::Client with pooled connections and explicit timeouts.

- (decision) AD-8: Concurrency bounding for blocking tasks. Binds: AD-1 (tokio::task::spawn_blocking). Prevents: OS thread pool exhaustion and DoS under high concurrent load when requests time out. Rule: Limit the number of concurrent ML inference jobs using a static tokio::sync::Semaphore matching the physical CPU core count.
- (decision) AD-9: Single-pass text replacement. Binds: AD-2, AD-3, and AD-6. Prevents: String offset shifting and Rust UTF-8 slicing panics during multi-stage redaction. Rule: Perform Regex scanning (Tier 1) and NER inference (Tier 2) on the original unmodified text to build character offset spans. Resolve overlaps first, then apply co-reference mapping in a single, final mutation pass.
- (decision) AD-10: Ephemeral Map Concurrency. Binds: AD-6 (Co-Reference Mapping). Prevents: Multi-threaded borrow checker conflicts on the ephemeral translation map. Rule: Redact messages within a single completions request sequentially on the blocking thread pool worker, ensuring single-threaded ownership of the translation map.
- (decision) AD-11: Proxy Header Rewriting. Binds: AD-7 (Forwarder). Prevents: TLS connection pool errors, host name mismatches, and request size inconsistencies. Rule: The proxy client must overwrite the Host header with the target upstream domain, drop hop-by-hop headers, and recalculate Content-Length based on the mutated payload size.
