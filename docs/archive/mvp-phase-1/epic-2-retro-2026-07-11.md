## ✅ What Went Well & Technical Strengths
1. **Low-Latency Regex Engine**: Compiling regexes once at startup keeps scan overhead below 1ms.
2. **Co-Reference Context Preservation**: Identical PII formats receive the same token (e.g. `[REDACTED_SSN_1]`), preserving relational context for upstream LLMs.
3. **Robust Overlap Resolution**: Resolving intersecting byte offsets (e.g. phone numbers nested inside credit cards) avoids token fragmentation.
4. **Comprehensive Test Suite**: Unit tests in [src/redact.rs](file:///Users/devgoyal/desktop/llm-firewall-rs/src/redact.rs) verify all regex boundary patterns, unicode normalization bypasses, and multi-message coreferences.

## ⚠️ Challenges & Friction Points
1. **Missing Message Content**: Handled completions payloads where `content` fields were null or omitted (e.g., tool/function responses) without failing-closed.
2. **Multimodal Payload Exclusions**: Had to prevent redaction of binary and URL values under `image_url` fields in message blocks.
3. **Boundary delimeters**: CC and Phone patterns had to be extended to support varying separators and spaces without leaking plaintext tail-ends.
